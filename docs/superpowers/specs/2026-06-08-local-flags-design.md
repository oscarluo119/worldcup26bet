# 本地国旗渲染设计

## 目标

把项目里依赖外部来源的国旗展示统一替换为本地静态资源渲染，覆盖比赛列表、积分榜、详情页和用户“看好冠军”相关展示；不再依赖 API 返回的队徽/旗帜图片，也不再依赖 `flagcdn.com`。

## 范围

本次改动包含：

- 为世界杯相关国家和队伍准备本地 SVG 国旗资源
- 建立统一的本地国旗映射层
- 把比赛 UI 中的 `homeLogo` / `awayLogo` 渲染切换为本地国旗
- 把“看好冠军”区域从 `flagcdn.com` 切换到本地国旗
- 添加回归测试，锁住“不再使用外部国旗地址”的行为

本次改动不包含：

- 删除 API 数据里的 `homeLogo` / `awayLogo` 字段
- 重构比赛数据结构
- 替换用户头像里已有的 emoji 存储格式
- 改动非世界杯国旗以外的图标资源

## 现状

当前仓库里有两套国旗来源：

1. 比赛和积分榜等主 UI 使用 API 返回的 `fixture.home.logo` / `fixture.away.logo`，映射到 `match.homeLogo` / `match.awayLogo` 后再交给 `TeamLogo` 渲染。
2. “看好冠军”区域通过 `countryCode` 拼接 `https://flagcdn.com/${team.countryCode}.svg`。

这导致：

- 页面依赖外部网络和第三方静态资源
- 比赛区与用户偏好区使用两套不同渲染链路
- 特殊队伍（如英格兰）需要额外适配时，没有统一入口

## 设计方案

### 方案概述

新增一层本地国旗注册表，统一处理“队伍名称/代码 -> 本地 SVG 资源”的映射。所有国旗展示都走这一层，不再直接信任 API `logo`，也不再拼接 `flagcdn.com` URL。

### 文件组织

新增目录：

- `src/assets/flags/`

目录中存放本地 SVG 文件，文件名使用稳定 key 命名，例如：

- `fr.svg`
- `es.svg`
- `ar.svg`
- `gb-eng.svg`
- `pt.svg`

新增模块：

- `src/lib/flags.js`

职责：

- 导入本地 SVG 资源
- 维护 key 到资源的映射
- 维护队名、英文名、国家代码等别名映射
- 暴露统一 helper 给 UI 层使用

## 数据与映射设计

### 统一 key

采用与现有 `FAVORITE_TEAM_OPTIONS.countryCode` 一致的 key 体系作为主键，例如：

- `fr`
- `es`
- `ar`
- `gb-eng`
- `pt`

这样可以直接复用用户偏好里的国家代码语义，也便于处理非标准国家代码场景。

### 映射来源

映射层支持三类输入：

1. 中文队名，例如 `法国`、`英格兰`
2. 英文队名，例如 `France`、`England`
3. 现有偏好项里的 `countryCode`

映射层内部会把这些输入归一化后映射到统一 key，再返回本地资源路径。

### 特殊名称处理

为了避免真实数据命名不一致导致丢旗，映射表会显式保留特殊别名，例如：

- `England` / `英格兰` -> `gb-eng`
- `USA` / `United States` / `美国` -> `us`
- `Netherlands` / `荷兰` -> `nl`

如果后续 API 命名还有轻微差异，新增别名即可，不需要改渲染组件。

## 渲染设计

### 比赛与榜单

`TeamLogo` 不再把 API `logo` 当作主要数据源，而是改成优先通过队名从本地映射层拿国旗资源。

新的优先级：

1. 通过本地映射命中 SVG
2. 如果未命中且有 emoji 可用，显示 emoji
3. 再不行显示当前 `?` 占位

这样即使某个队名暂时漏配，页面也能优雅降级，不会出现图片断链。

### 用户偏好与冠军选择

当前“看好冠军”展示中通过 `countryCode` 拼接 `flagcdn.com` 的位置，改为使用同一份本地映射层。

新的优先级：

1. `countryCode` 命中本地 SVG
2. 回退到当前已有 `flagEmoji`
3. 再回退到白旗或占位

### API 字段保留策略

`homeLogo` / `awayLogo` 字段和现有数据映射逻辑先保留，不做删除。

原因：

- 避免扩大改动面
- 保持数据兼容
- 如果后续要做更深入清理，可以在另一轮中移除未使用字段

本轮只调整渲染层，不改底层数据装配。

## 组件边界

### `src/lib/flags.js`

建议暴露的接口：

- `getFlagAssetByCountryCode(countryCode)`
- `getFlagAssetByTeamName(name)`
- `getFlagRenderData({ teamName, countryCode, fallbackEmoji })`

其中 `getFlagRenderData` 返回渲染所需的统一结构，例如：

- `type: "image" | "emoji" | "fallback"`
- `src`
- `emoji`
- `alt`

这样 UI 组件不用知道映射细节，只根据返回结构渲染。

### `TeamLogo`

`TeamLogo` 改成只关注展示，不负责决定映射规则。它接收队名和可选 fallback 信息，从 helper 拿到渲染数据后输出图片、emoji 或占位。

### 用户偏好国旗组件

当前直接拼 `flagcdn` 的组件也复用同一个 helper，避免第二套逻辑继续存在。

## 错误处理与回退

本地国旗缺失时，页面行为定义如下：

- 比赛/榜单：显示 emoji；如无 emoji，显示 `?`
- 用户偏好：显示该队已有 emoji；如无 emoji，显示白旗

不抛异常，不阻断页面渲染。

## 测试方案

### 自动测试

新增聚焦测试，至少覆盖：

- 常见队名如 `法国` 能映射到本地资源
- 特殊队名如 `英格兰` 能映射到本地资源
- 渲染源码中不再包含 `flagcdn.com`

如果测试方式以 helper 为主，可以直接验证 `getFlagRenderData` 的输出；这样比直接做整页渲染更稳定。

### 手工验证

本地页面启动后，重点检查：

- 比赛列表中的法国、西班牙、英格兰
- 积分榜中的队伍国旗
- 个人偏好或冠军选择中的国旗显示
- 网络面板里不再请求 `flagcdn.com`
- 页面在离线或弱网条件下仍能正常展示国旗

## 风险与对应策略

### 风险 1：队名不统一导致映射漏掉

策略：

- 显式维护别名表
- 先覆盖当前仓库与 API 中已出现的队名
- 保留 emoji 和占位回退，避免页面空白

### 风险 2：资源文件很多，入口文件继续膨胀

策略：

- 把所有国旗导入和映射从 `App.jsx` 抽离到 `src/lib/flags.js`
- 维持 `App.jsx` 只做组件调用

### 风险 3：英格兰等特殊旗帜命名不规范

策略：

- 使用显式 key `gb-eng`
- 不依赖运行时猜测 ISO 代码

## 兼容性结论

这个方案对现有业务兼容性高：

- 不改接口
- 不改数据库
- 不改比赛数据结构
- 只替换渲染来源

因此适合用较小风险完成“本地渲染国旗、替代外部旗帜来源”的目标。
